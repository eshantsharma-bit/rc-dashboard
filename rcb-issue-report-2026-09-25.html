Case Counting Methodology

  • 80 explicitly verified cases are the deduplication-confirmed set. Zero duplicate Case IDs detected.
  • Full-dataset figure of 682+ is derived from stated SOQL batch totals: 332 (Jun–Jul) + 350 (Aug–Sep) + unquantified Feb–May.
  • The full 600+ non-enumerated cases were not available at case level — bug rate and issue categories are based on the 80 verified cases only.
  • Severity classifications are taken directly from the Priority field in OrgCS.

Category Classification Rules

  • Product Bug: GUS/W-number filed, or error is clearly a platform defect with no config resolution.
  • Data/Calculation Error: Correct config, incorrect output — wrong amounts, wrong dates, wrong records.
  • Configuration/Implementation: Customer is using the product incorrectly or needs guidance on correct setup.
  • Customisation Conflict: Customer code (trigger/flow) is conflicting with the billing engine — product has no guardrail.
  • Unclassified: Case has insufficient documented evidence in comments to confirm primary root cause.
