⚠ Invoice Generation — Two Systemic Gaps (105 cases)

1 · Error Messages Are Not Actionable
Customers and support engineers see generic system-level errors — System.UnexpectedException: Missing data, ARM Invoice Generation Error, TaxCalculationFailed — with no indication of which record failed, which field is wrong, or what to fix. Cases for the same underlying root cause arrive worded differently from every customer because each one is guessing from the error surface they see. Support spends first-response time just decoding what actually failed.
2 · Invoices Stuck in Intermediate State — Support Has No Recovery Path
When an invoice enters a partial or stuck state (pending generation, generation initiated but not completed, batch partially run), support has no documented recovery playbook. There is no "how to recover a stuck invoice" KB article. Every such case becomes an engineering escalation — support cannot unblock the customer independently. This is a repeating pattern: the same escalation loop is occurring across different accounts and different engineers, with no institutional resolution.
Product signal: This is a tooling + documentation gap, not a one-off bug. Better error messages = fewer escalations per case. Recovery documentation = support closes these without engineering. Both are leverage points.
